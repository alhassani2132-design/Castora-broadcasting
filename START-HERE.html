Deploy Castora on Netlify

This package contains the real Next.js application: live studio, host control room, saved events, email invitations and reminders, chat, Q&A, polls, attendance analytics, provider-side cloud recording and a private replay library.

This is a source-code deployment package.

Use Netlify’s Git import or the Netlify CLI. The drag-and-drop static-site upload does not build the server routes needed for login, saved events and streaming tokens.

Required services: Netlify for the website, Supabase for accounts/events/analytics, LiveKit for live media, and a production email sender in Supabase for sign-in. Optional production integrations: Resend for event invitations/reminders and S3-compatible object storage for cloud recordings.

01 Set up Supabase

  1. Create a project at Supabase.
  2. Open the SQL Editor. Paste the complete contents of supabase/setup.sql from this package and run it. It creates Castora’s tables, server-only access rules, and a private recordings bucket.
  3. Under the project’s API settings, copy the project URL, legacy anon key and legacy service_role key. Keep the service-role key private.
  4. Enable email sign-in and allow new users to sign up. Keep email confirmation enabled.
  5. In Authentication → Email Templates, change the Magic Link template to the snippet below. If a separate Confirm signup template is used in your project, use the same code snippet there too.
<h2>Your Castora sign-in code</h2>
<p>Enter this code in Castora:</p>
<p style="font-size:28px;font-weight:bold">{{ .Token }}</p>

Castora accepts a numeric email code, not a magic-link redirect. Configure your own SMTP sender in Supabase before inviting your audience. Supabase’s default sender is for testing with authorized team addresses and is not suitable for a 500-person event. Set email delivery/rate limits for your expected registration volume. See Supabase SMTP instructions.

02 Connect the code to Netlify

  1. Extract the ZIP. The project root is the folder containing package.json and netlify.toml.
  2. Upload those files to a Git repository you own, preserving the folders and the lockfile.
  3. In Netlify, add a project and import that repository. Select the correct base directory if the project is in a subfolder.
  4. Use the settings below. netlify.toml already supplies them.
SettingValue

Build commandpnpm run build

Do not use out, dist, or the project root as the publish directory. Netlify automatically provides the current Next.js adapter. Do not install the older plugin version from your pharmacy portal.

03 Add environment variables

In Netlify’s environment-variable settings, add these values with Functions scope. If your interface offers only “all scopes,” use that. Use the exact uppercase names.

SUPABASE_ANON_KEYThe project’s legacy anon key
SUPABASE_SERVICE_ROLE_KEYThe project’s legacy service_role key — secret

Never put secrets in source code or prefix them with NEXT_PUBLIC_. The browser receives short-lived room tokens and signed upload links, not service credentials. You can deploy before adding LiveKit values to set up events; going live stays unavailable until they are added.

04 Deploy and sign in

  1. Run the Netlify deployment. Add your final HTTPS site address as the Site URL in Supabase’s Authentication URL settings.
  2. Open your Netlify address and sign in with the email listed in CASTORA_HOST_EMAILS.
  3. Enter the code delivered by email. If Create event is disabled, check the host email list and redeploy after correcting it.
  4. Create an event. Copy its audience link. Guests sign in using their own email. Private events also require the invitation link.
  5. Test with a second device/account before inviting attendees. Use the People panel to grant camera/microphone permission.

After changing environment values, deploy again. If you see a storage setup error, check that the SQL was run in the same Supabase project as the keys.

Command-line deployment alternative

If you prefer a terminal, run these commands from the extracted project directory. The first deployment is a preview; check it before the production command.

corepack enable
pnpm install --frozen-lockfile
npx netlify-cli login
npx netlify-cli init
npx netlify-cli deploy --build
# After configuring variables and reviewing the preview:
npx netlify-cli deploy --build --prod

05 Prepare for 500+ attendees

Choose a LiveKit plan with sufficient concurrent connections, bandwidth and limits. This version uses up to 10 stage speakers and host-approved participation in both modes. The Host Control Room adds stage locking, chat/Q&A pause controls and slow mode for large audiences. A room’s configured 1,000-person limit does not guarantee your provider plan can support it. Arrange email capacity too, and rehearse with a representative load.

Screen recording captures the screen and audio your browser shares; it does not automatically mix microphone audio. It stops near 45 MB, downloads locally and uploads to your private library. Uploads accept MP4, WebM and MP3 up to 50 MB. Full-session cloud recording is available from the Host Control Room after the recording storage variables are configured.

What to verify after deployment

This updated package includes source-level checks, but the final production build must run in Netlify where dependencies can be installed. Verify Supabase migrations, email delivery, LiveKit connectivity, scheduled reminders and cloud recording with your connected accounts. Large-audience capacity still requires a rehearsal/load test with your chosen LiveKit plan.

Run the updated supabase/setup.sql even if you previously ran an older Castora setup; it adds the controls, invitation, analytics and cloud-recording tables without deleting the core tables. Chat, Q&A and polls remain live-session state. Attendance and watch-time analytics are approximate and sampled through heartbeats.
